# CWLauncher 2.5.3 — SIGABRT и файловый менеджер

Дата: 18 октября 2026 года.

## Диагностический результат

Исследован `cwlauncher-diagnostics-1792333613846.zip`. Предыдущая ошибка `Font.initIDs()` больше не возникает. Фактическая последовательность новой попытки:

1. GL4ES запускается.
2. Системные GLES/EGL загружаются.
3. Поверхность Android передаётся графическому мосту.
4. Выполняется вход в `JNI_CreateJavaVM`.
5. HotSpot начинает native-регистрацию.
6. Появляются предупреждения о повторной регистрации `NativeLibraries.load` и `ProcessImpl.forkAndExec`.
7. Последняя native-строка: `Pointer tag ... was truncated`.
8. `latest.log` и `fabric.log` не создаются — `KnotClient` не дошёл до собственного логирования.
9. Android завершает `ru.cw.launcher:game` с `reason=SIGNALED`, `androidStatusRaw=6`. Это Android signal/status, не Java exit code.

Полного tombstone/backtrace в архиве нет. Поэтому конкретную native-инструкцию, вызвавшую SIGABRT, нельзя считать подтверждённой системным стеком. Однако аудит исходного кода обнаружил две реальные ошибки именно на пути между `JNI_CreateJavaVM` и Java main, согласующиеся с последней строкой журнала.

## Найденные native-дефекты

### Неверный размер выделения памяти

Структура `heap_str_array` выделялась так:

```c
malloc(sizeof(heap_str_array*) + count * sizeof(const char*))
```

То есть использовался размер указателя вместо размера структуры. Исправлено на `sizeof(heap_str_array)`, добавлены проверка `NULL` и нулевая инициализация.

### Освобождение Android-tagged pointers после старта HotSpot

Строки VM options и application args создавались Android allocator, передавались через JNI/HotSpot, а затем освобождались сразу после создания JVM или преобразования аргументов. На Android 15 последняя запись перед SIGABRT сообщает об усечении pointer tag. Теперь эти небольшие launch-блоки живут до завершения отдельного игрового процесса. Это устраняет опасный `free()` для указателей, прошедших через встроенную JVM.

Это доказанный дефект управления памятью и наиболее сильный кандидат на текущий SIGABRT. Окончательное подтверждение непосредственной точки abort возможно только свежим запуском или tombstone.

### Повторная JNI-регистрация

`NativeLibraries.load` регистрируется class-loader hook, необходимым для загрузки JRE-библиотек в Android namespace. Само предупреждение не доказывает падение.

Повторная регистрация `ProcessImpl.forkAndExec` была необязательной — она нужна только для перенаправления отдельных внешних программ. В журнале она происходила непосредственно перед abort. Этот hook отключён; Minecraft использует `-Djdk.lang.Process.launchMechanism=FORK`, но для запуска `KnotClient` подмена метода не требуется.

### Дополнительные исправления native lifecycle

- удалён двойной вызов `DestroyJavaVM` на пути нормального возврата;
- добавлены стадии `CW-JVM stage 1` … `CW-JVM stage 6`;
- сохранён захват stdout/stderr;
- сохранена корректная неизвестная причина завершения при Android signal;
- `statusRaw=6` нигде не подменяется Java exit code 0.

## Контрольные native-стадии

Новый `jvm.log` позволит определить границу:

- stage 1 — вход в `JNI_CreateJavaVM`;
- stage 2 — HotSpot создан;
- stage 3 — установлен hook загрузки native-библиотек;
- stage 4 — необязательный ProcessImpl hook пропущен;
- stage 5 — Java-массив игровых аргументов создан;
- stage 6 — вызывается `net.fabricmc.loader.impl.launch.knot.KnotClient.main`.

Если процесс завершится между стадиями, архив даст существенно более точную область сбоя даже без системного Logcat.

## Файловый менеджер

Изменён `Screens.kt`:

- панели с большим количеством действий переведены с одной неограниченной строки на `FlowRow`;
- кнопки автоматически переносятся на следующую строку с постоянными интервалами 6 dp;
- исправлены панели `Копировать`, `Переместить`, `Переименовать`, `Отправить`, `Копировать путь`, `Удалить`, `Закрыть`;
- верхняя панель просмотрщика разделена на заголовок и переносимую панель действий;
- поиск и сортировка больше не конкурируют за ширину одной строки;
- промежуток перед первым элементом списка сокращён до 2 dp;
- нажатие на любой файл по-прежнему сразу открывает встроенный просмотрщик;
- текстовые расширения: `txt`, `log`, `json`, `properties`, `cfg`, `toml`, `yml`, `yaml`;
- сохранены постраничное чтение по 256 КиБ, поиск по тексту, UTF-8, возврат и копирование пути.

Статически и компиляцией подтверждено отсутствие конфликтов Compose layout. Визуальная проверка на экране TECNO LI6 ещё требуется.

## Статус критериев приёмки

На момент сборки ADB показывает пустой список устройств. Поэтому нельзя честно подтвердить установку этого нового APK или главное меню.

1. Установка приложения — **не проверена**, устройство не подключено.
2. Создание JVM — **подтверждено старым запуском**, но новая native-сборка на устройстве ещё не проверена.
3. Отсутствие SIGABRT — **не проверено после исправления**; причина сужена до доказанных memory-management дефектов, tombstone отсутствует.
4. GL4ES/GLES/EGL — **подтверждены журналом предыдущей попытки**.
5. Fabric/Minecraft main — **не подтверждены**; их журналы отсутствуют.
6. Окно и главное меню — **не подтверждены**.
7. Открытие текста одним нажатием — реализовано и скомпилировано, **нужен тест касанием**.
8. Отсутствие наложения — адаптивный layout реализован и скомпилирован, **нужна визуальная проверка**.
9. Лишний промежуток — код исправлен, **нужна визуальная проверка**.
10. Поиск/копирование пути — код присутствует и скомпилирован, **нужен тест на устройстве**.
11. Подробное логирование/экспорт — код и предыдущий ZIP подтверждают работу экспорта; переключатели требуют интерактивного теста.

## Следующая проверка

Установить APK, выполнить ровно один запуск и сразу экспортировать ZIP. Успешный переход должен показать stages 1–6, затем строки Fabric/Minecraft и создание `latest.log`.

Для системного стека:

```powershell
adb logcat -c
# Запустить игру и дождаться сбоя
adb logcat -d -v threadtime > cwlauncher-logcat.txt
adb shell dumpsys activity exit-info ru.cw.launcher > cwlauncher-exit-info.txt
```

Не фильтровать исходный Logcat. В копии искать `ru.cw.launcher:game`, `SIGABRT`, `FATAL`, `DEBUG`, `libc`, `linker`, `tombstone`, `HotSpot`, `pojavexec`.

Minecraft не объявлен запущенным: текущие доказательства заканчиваются созданием JVM и инициализацией GL4ES/EGL.
